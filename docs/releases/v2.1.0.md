# WIP v2.1.0

**Released:** 2026-07-26 (draft — pending tag)
**Previous stable:** v2.0.0 (2026-07-18)
**Commits since v2.0.0:** 189

The headline of this release is **restore grown into a three-mode
operation** — id-preserving `restore`, reconciling `merge`, and
identity-minting `fresh` — hardened by a 24-cell backup/restore test
matrix that was driven to green against live deployments, finding and
fixing seven platform defects along the way. Around it: template
identity became registered and upsert-based, term addressing went
strict, every service enforces strict request models, and the archive
machinery moved into a shared library with exactly one import
write-path.

---

## Action required / behavior changes (read before upgrading)

### Term addressing is strict — the 2-part shorthand is rejected

`TERMINOLOGY:VALUE` is rejected with 422 on **every** term endpoint,
reads and writes alike (CASE-776, CASE-778). A value containing `:`
(OBO ids like `GO:0000278`) is indistinguishable from the shorthand, so
it could silently select a term in the wrong terminology. Accepted
forms: canonical UUID, fully qualified `ns:terminology:value`, or the
field form (a `terminology` parameter scoping an opaque value).
**Action:** callers using the 2-part form must switch; prefer the field
form.

### Strict request models everywhere

All services reject unknown keys in request bodies, enforced by a
route-walking CI gate (and re-armed after it silently no-opped on
FastAPI ≥ 0.139, CASE-786). Sloppy payloads that used to be silently
pruned now 422. Registry grant endpoints included.

### Template create is an upsert; deactivation needs a version

The template's identity is its `(namespace, value)` name, registered
with the Registry (CASE-709). Re-POSTing an existing template is a
version event — `created` / `unchanged` / `updated` with a structured
schema diff; identity or immutable-property changes are rejected per
item (`identity_fields_immutable` / `immutable_property`). The
`on_conflict` parameter is deprecated (accepted, ignored).
`deactivate_template` now requires an explicit `version` (CASE-766).

### Restore surface: the client-side importer is gone; refusals are loud

- The wip-toolkit **importer was deleted** (CASE-744): the platform has
  one import write-path — the server restore engine. The CLI is
  export-only; upload archives to `POST
  /backup/namespaces/{ns}/restore`.
- Toolkit-era parameters on the server backup/restore endpoints now
  **400 loudly** instead of being ignored (CASE-705, CASE-548).
- `register_synonyms` is removed from fresh restore — fresh means
  fresh; a restored copy is severed from its source (CASE-743).
- A restore of an archive carrying entity rows but **no registry
  identity rows** (e.g. a `--skip-synonyms` CLI export) is **refused**
  up front; `allow_missing_identity=true` overrides with a warning
  (CASE-824).

### One pagination contract

List endpoints uniformly default to `page_size` 50 with max 1000; two
documented deviations (relationships endpoint caps at 500, table view
defaults to 100) (CASE-790).

## New capabilities

### Restore modes: restore, merge, fresh

- **`mode=merge`** — the archive as a delta against a live, possibly
  non-empty namespace: two-pass (definitions gate first, then data),
  per-document clash policy `skip` / `overwrite` / `newer`,
  `add_missing` and `extend_terminologies` as separate explicit
  decisions, cross-namespace target honored, and refusal of references
  that would resolve to nothing.
- **`mode=fresh`** — every entity re-registered with a Registry-minted
  id and every reference rewritten, so a namespace can be restored
  beside the one it came from. Multi-namespace archives via an explicit
  `namespace_map`; id-identity keys claimed at activation (CASE-787);
  the target does not inherit the source's `id_config` (CASE-784);
  value-form + custom synonyms carry onto re-minted entities
  (CASE-792).
- **Post-restore integrity validation** — every restore auto-spawns a
  per-namespace validation job (references + identity hashes), linked
  on the restore job; non-healthy findings are mirrored onto the
  restore job's own warnings (CASE-824). A standing
  `POST /backup/namespaces/{ns}/validate` runs the same check on
  demand.
- Real `dry_run` across all three modes, with the plan surviving on the
  job record; typed archive errors refuse malformed uploads
  synchronously (CASE-783); backups are full copies with deterministic
  export order (CASE-768, CASE-772); throughput work on bulk activation
  and batch sync (CASE-740, CASE-741).

### The backup/restore test matrix (CASE-773)

A producer × mode × seam matrix — 24 cells, component tier plus a
manual layer-L runner pointed at named deployments — completed 24/24
green against live k8s installs, including cross-instance DR. Matrix
work attributed and fixed seven platform defects, among them: fresh
restores dropping qualified cross-namespace refs (CASE-814), the N:1
merge collision check comparing at the wrong key (CASE-815), read-door
resolution lagging the write door (CASE-816), and timestamp filters
blind to one BSON type (CASE-821).

### Template identity & schema evolution

- Version-event **impact analysis** and **declared renames**, with
  candidate validation honoring them (CASE-711, CASE-717).
- **Per-version reporting tables + entity views** — physical
  `doc_<value>__v<N>` tables per template version under a stable
  `doc_<value>` view (CASE-710), with a typed cross-version view in the
  client (CASE-720).

### Archive & toolkit

- **`libs/wip-archive`** — the archive format (reader/writer/manifest)
  and the id remapper moved to a shared library consumed by both the
  toolkit and the server engine (CASE-744).
- CLI exports carry **raw registry identity rows**, making CLI archives
  restorable by the server engine with identity intact (CASE-756).
- The default CLI export now **says what it drops**: without
  `--include-inactive` it carries latest active versions only, warns
  loudly, and stamps the manifest honestly (CASE-823). Audit of the
  full export-flag surface recorded in CASE-819; the agreed direction
  (one collector, archive-native transforms) in FIRESIDE-27.

### Term addressing & vocabulary

- Field-form term addressing on all twelve term doors; colon-carrying
  values resolve safely (CASE-776, CASE-778).
- OBO import detects term prefixes from node data and refuses an empty
  match (CASE-775); terminology import `update_existing` is extend-only
  with honest per-item status (CASE-797); ambiguous unscoped
  terminology-value reads fail loud (CASE-763); system terminologies
  resolve by value (CASE-791).

### Deployer & operations

- `--api-keys-file` for human-friendly key declaration (CASE-696) and a
  `rotate-key` verb for spec-declared config keys (CASE-698).
- k8s: `imagePullPolicy` covers WIP apps (CASE-697); pod `dnsConfig`
  rendered with `ndots:1` (CASE-807); `verify --security` resolves
  hostnames before flagging TLS (CASE-695).
- Health checks cache the probe path and run dependency checks
  concurrently (CASE-808); S3 client timeouts bounded (CASE-806).

### Clients, MCP, and docs

- MCP server now exposes **101 tools** and 5 resources.
- `@wip/client` 0.50.0, `@wip/react` 0.19.0, `@wip/proxy` 0.5.1,
  `wip-auth` 0.5.1.
- `@wip/proxy` streams both directions with backpressure — proxy memory
  is O(1) in payload size (CASE-753); `resolveApiKey` falls back from a
  failed `apiKeyFile` to the inline key (CASE-714).
- Documentation-accuracy sweep across served resources, OpenAPI
  descriptions, and design docs (CASE-789, CASE-793–796), gated by a
  tracked-docs ↔ KB drift check (CASE-723).
