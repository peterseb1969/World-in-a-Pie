# WIP v2.1.0

**Released:** 2026-07-27
**Previous stable:** v2.0.0 (2026-07-18)
**Commits since v2.0.0:** 195

The headline of this release is **restore grown into a three-mode
operation** — id-preserving `restore`, reconciling `merge`, and
identity-minting `fresh` — hardened by a 24-cell backup/restore test
matrix that was driven to green against live deployments, finding and
fixing seven platform defects along the way. Around it: template
identity became registered and upsert-based, term addressing went
strict, every service enforces strict request models, and the archive
machinery moved into a shared library with exactly one import
write-path.

---

## Action required / behavior changes (read before upgrading)

### Term addressing is strict — the 2-part shorthand is rejected

`TERMINOLOGY:VALUE` is rejected with 422 on **every** term endpoint,
reads and writes alike. A term value containing `:` (OBO ids like
`GO:0000278`) is indistinguishable from the shorthand, so it could
silently select a term in the wrong terminology. Accepted forms:
canonical UUID, fully qualified `ns:terminology:value`, or the field
form (a `terminology` parameter scoping an opaque value).
**Action:** callers using the 2-part form must switch; prefer the field
form.

### Strict request models everywhere

All services reject unknown keys in request bodies, enforced by a
route-walking CI gate (re-armed after a FastAPI upgrade had silently
disabled it). Sloppy payloads that used to be silently pruned now 422.
Registry grant endpoints included.

### Template create is an upsert; deactivation needs a version

The template's identity is its `(namespace, value)` name, registered
with the Registry. Re-POSTing an existing template is a version event —
`created` / `unchanged` / `updated` with a structured schema diff;
identity or immutable-property changes are rejected per item
(`identity_fields_immutable` / `immutable_property`). The `on_conflict`
parameter is deprecated (accepted, ignored). Deactivating a template
now requires an explicit `version`.

### Restore surface: the client-side importer is gone; refusals are loud

- The wip-toolkit **importer was deleted**: the platform has one import
  write-path — the server restore engine. The CLI is export-only;
  upload archives to `POST /backup/namespaces/{ns}/restore`.
- Legacy toolkit-era parameters on the server backup/restore endpoints
  now **400 loudly** instead of being ignored.
- Synonym back-registration is removed from fresh restore — fresh means
  fresh; a restored copy is severed from its source.
- A restore of an archive carrying entity rows but **no registry
  identity rows** (e.g. a `--skip-synonyms` CLI export) is **refused**
  up front; `allow_missing_identity=true` overrides with a warning.

### One pagination contract

List endpoints uniformly default to `page_size` 50 with max 1000; two
documented deviations (the relationships endpoint caps at 500, table
view defaults to 100).

## New capabilities

### Restore modes: restore, merge, fresh

- **`mode=merge`** — the archive as a delta against a live, possibly
  non-empty namespace: two-pass (definitions gate first, then data),
  per-document clash policy `skip` / `overwrite` / `newer`,
  `add_missing` and `extend_terminologies` as separate explicit
  decisions, cross-namespace target honored, and refusal of references
  that would resolve to nothing.
- **`mode=fresh`** — every entity re-registered with a Registry-minted
  id and every reference rewritten, so a namespace can be restored
  beside the one it came from. Multi-namespace archives via an explicit
  `namespace_map`; id-identity keys are claimed at activation; the
  target does not inherit the source's id-generation config; value-form
  and custom synonyms carry onto the re-minted entities.
- **Post-restore integrity validation** — every restore auto-spawns a
  per-namespace validation job (references + identity hashes), linked
  on the restore job; non-healthy findings are mirrored onto the
  restore job's own warnings. A standing
  `POST /backup/namespaces/{ns}/validate` runs the same check on
  demand.
- Real `dry_run` across all three modes, with the plan surviving on the
  job record; typed archive errors refuse malformed uploads
  synchronously; backups are full copies with deterministic export
  order; bulk-activation and batch-sync throughput work landed
  alongside.

### The backup/restore test matrix

A producer × mode × seam matrix — 24 cells, a component tier plus a
manual layer-L runner pointed at named deployments — completed 24/24
green against live Kubernetes installs, including cross-instance
disaster recovery. Matrix work attributed and fixed seven platform
defects, among them: fresh restores dropping qualified cross-namespace
references, the N:1 merge collision check comparing at the wrong
uniqueness level, read-path identifier resolution lagging the write
path, and timestamp filters blind to one of two BSON date encodings.

### Template identity & schema evolution

- Version-event **impact analysis** and **declared renames**, with
  candidate validation honoring them.
- **Per-version reporting tables + entity views** — physical
  `doc_<value>__v<N>` tables per template version under a stable
  `doc_<value>` view, with a typed cross-version view in the client.

### Archive & toolkit

- **`libs/wip-archive`** — the archive format (reader/writer/manifest)
  and the id remapper moved to a shared library consumed by both the
  toolkit and the server engine.
- CLI exports carry **raw registry identity rows**, making CLI archives
  restorable by the server engine with identity intact.
- The default CLI export now **says what it drops**: without
  `--include-inactive` it carries latest active versions only, warns
  loudly, and stamps the manifest honestly. A full audit of the export
  flag surface was run end-to-end against a live instance; the agreed
  longer-term direction is a single collector (the server engine) with
  archive-native transforms in the CLI.

### Term addressing & vocabulary

- Field-form term addressing on all term endpoints; colon-carrying
  values resolve safely.
- OBO import detects term prefixes from node data and refuses an empty
  match; terminology import's update mode is extend-only with honest
  per-item status; ambiguous unscoped terminology-value reads fail
  loud; system terminologies resolve by value.

### Deployer & operations

- `--api-keys-file` for human-friendly key declaration and a
  `rotate-key` verb for spec-declared config keys.
- Kubernetes: `imagePullPolicy` covers WIP apps, not just locally built
  images; pod `dnsConfig` rendered with `ndots:1`;
  `verify --security` resolves hostnames before flagging TLS.
- Health checks cache the probe path and run dependency checks
  concurrently; S3 client timeouts are bounded.

### Clients, MCP, and docs

- MCP server now exposes **101 tools** and 5 resources.
- `@wip/client` 0.50.0, `@wip/react` 0.19.0, `@wip/proxy` 0.5.1,
  `wip-auth` 0.5.1.
- `@wip/proxy` streams both directions with backpressure — proxy memory
  is O(1) in payload size; `resolveApiKey` falls back from a failed
  `apiKeyFile` to the inline key with a startup warning.
- A documentation-accuracy sweep aligned served resources, OpenAPI
  descriptions, and design docs with the shipped code, gated by a
  standing check that tracked docs and their knowledge-base records do
  not drift.

## Known items

- The backup/restore matrix has open follow-ups: an operator
  walkthrough of its fixture design, and per-cell runner selection so a
  single cell can be re-run in isolation. The routine non-perturbing
  matrix invocation is the standing pre-release check; formalizing that
  mechanism (runbook vs. deployer verb vs. CI) is decided-in-principle
  but not yet built.
- `@wip/client`'s README documents the service surface through the
  client properties; a majority of the raw export surface (types,
  helpers) remains README-undocumented — tracked as a doc-coverage
  item, not a gate.
- The single-collector toolkit direction (retire the CLI's client-side
  collector in favor of engine backups plus archive-native transforms;
  add thin `backup`/`restore` CLI verbs) is agreed but not yet designed
  or scheduled.
