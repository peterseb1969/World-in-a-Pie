# WIP v2.0.0

**Released:** 2026-07-18
**Previous stable:** v1.1.0 (2026-04-13)
**Commits since v1.1.0:** 591

The headline of this release is a **breaking change to how WIP is
installed and operated**, on top of a large additive expansion of the
data model, the deployer, and the client libraries. The major-version
bump signals the install-path replacement and the fail-loud registry
claim semantics — both require action from operators upgrading an
existing instance.

---

## Breaking changes (read before upgrading)

### The legacy install path is gone; wip-deploy v2 is the only deployer

`scripts/setup.sh`, `scripts/setup-wip.sh`, and the hand-maintained
`k8s/` manifests have been **retired and deleted**. All deployment now
flows through `wip-deploy` (the `deployer/` package): one spec layer
feeding three targets — `compose`, `dev`, and `k8s`.

- **Action:** re-provision existing instances with
  `wip-deploy install`. See `docs/deployment/` and the WIP Guide.
- The spec → config_gen → per-target renderer architecture means all
  three targets render from the same routing/env/Caddy intermediate —
  no per-target drift.

### Registry composite-key claims fail loud

Claim resolution moved to a **two-phase (pending/confirmed) model**
(CASE-554). Cross-feed collisions that previously resolved silently now
**fail fast**; cross-owner orphaned claims heal-and-claim. This is
correct-by-design but changes observable behavior for any workflow that
depended on the old silent reconciliation.

### `--variant prod` arms production-safety guards

Installing with `--variant prod` (CASE-615) enables startup guards that
**reject the default dev API key** and other unsafe-for-production
configuration. A prod-variant install will refuse to start with
`dev_master_key_for_testing` present.

## New capabilities

### Data model

- **Edge types** (`usage: "relationship"`) — first-class relationship
  schemas with `source_ref`/`target_ref`, cross-namespace and
  archived-endpoint validation, and `/relationships` + `/traverse`
  query endpoints. Additive endpoint widening via
  `add_edge_type_endpoints` (CASE-515). PoNIF #7.
- **`versioned: false`** — edge types can opt out of versioning;
  updates overwrite in place. Requires non-empty `identity_fields`.
  PoNIF #8.
- **Identity-less (append-only) templates** — empty `identity_fields`
  is a first-class create-only mode; PATCH is rejected with
  `append_only` (CASE-478).
- **Metadata versions like data** — `metadata.custom` versions
  alongside `data` via `metadata_patch`, never feeding the identity
  hash (CASE-684).
- **Validated template-version migration** — `migrate_documents` /
  `POST /documents/migrate`, an identity-preserving bulk re-pin with
  dry-run (CASE-491).
- **Mandatory pinned versions on schema references** (CASE-493).

### Backup & restore

- **Multi-namespace v3 archive format** — backup/restore many
  namespaces in one archive (CASE-542, CASE-544).
- **Archives live in MinIO** when available, with download and
  restore-from-job for retained archives (CASE-543).
- **Phased restore verification + standing parity verb**
  (`check_reporting_parity`) — restore validates in phases and a
  standing verb confirms Mongo↔Postgres parity (CASE-689).
- Thread-based backup path retired for the async job model (CASE-549).
- Operations runbook: `docs/deployment/backup-restore.md`.

### Deployer & operations

- **`wip-deploy verify --security`** — read-only pre-exposure checklist
  (secret file permissions, API-key strength, TLS-vs-hostname,
  variant-vs-exposure, published ports, security headers) (CASE-445).
- **Spec-declared config-file API keys with local grants** — keys and
  their namespace grants declared in the deploy spec survive a MongoDB
  wipe/restore by construction, resolving locally with no Registry
  round-trip (CASE-655, CASE-693).
- **Hardening headers** rendered for letsencrypt installs (CASE-691).
- **Healthcheck probe-binary pre-flight** — the curl-or-wget invariant
  is checked before deploy (CASE-454).
- New verbs: `redeploy`, `app-deploy`, reversible `stop`/`start`,
  additive `add-app`/`remove-app`/`add-module`/`remove-module`
  (CASE-528, CASE-410, CASE-475, CASE-313).
- Bare-host root redirect for k8s + compose (CASE-368).

### Clients, MCP, and scaffold

- MCP server now exposes **98 tools**.
- `@wip/client` 0.34.0, `@wip/react` 0.19.0, `@wip/proxy` 0.4.2,
  `wip-auth` 0.5.0.
- Runtime app-config route — client-visible deploy values are fetched
  at runtime, not baked into the build (CASE-551).
- Scaffold engine + content-family delegation; versioned immutable lib
  tarballs replace the mutable `-latest.tgz` (CASE-612, CASE-442).

## Known items

- `GET /stamp` (template-store change-detection stamp) authenticates
  the caller but does not call a namespace permission helper — a
  read-only internal poll endpoint; flagged by api-consistency, to be
  either exempted with rationale or gated in a follow-up.
- UI-created runtime API keys remain wipe-mortal until backup coverage
  exists (spec-declared config keys from CASE-655 are the durable
  path).
